# 実装計画作成

issueの内容を分析し、実装計画を`plan.md`に作成します。

## 実行手順

1. **issueの内容を確認**
   ```bash
   gh issue view {ISSUE_NUMBER}
   ```

2. **関連ファイルを調査**
   - 変更が必要なファイルを特定
   - 既存のコードを読んで理解

3. **plan.mdを作成**
   プロジェクトルートに`plan.md`を作成し、以下の内容を記載：

## plan.mdのテンプレート

```markdown
# 実装計画

## Issue概要
<!-- issueのタイトルと内容を簡潔に記載 -->
- Issue番号: #
- タイトル:
- 要求内容:

## 影響範囲の分析
<!-- 変更が必要なファイルと理由を記載 -->
### 変更が必要なファイル
- `ファイル名`: 変更理由

### 影響を受ける機能
- 機能名: 影響内容

## 実装方針
<!-- どのようなアプローチで実装するか記載 -->

## 実装手順
<!-- 具体的な実装ステップを記載 -->
1.
2.
3.

## 変更内容の詳細
<!-- 各ファイルでどのような変更を行うか具体的に記載 -->

### ファイル名
```言語
// 変更前
古いコード

// 変更後
新しいコード
```

## 注意点
<!-- 実装時に注意すべき点を記載 -->
- XSS対策の確認
- 既存機能への影響確認
- エッジケースの考慮

## テスト計画
<!-- 実装後にどのようなテストを行うか記載 -->
1.

## 完了条件
<!-- どのような状態になれば完了とみなすか記載 -->
- [ ]
- [ ]
```

## 実行例

```bash
# 1. issueを確認
gh issue view 15

# 2. 関連ファイルを調査
cat style.css
cat index.html
cat app.js

# 3. plan.mdを作成
# 上記テンプレートに従って詳細な実装計画を記載
```

## plan.md作成のポイント

1. **具体的に書く**
   - 「色を変更する」ではなく「#ef4444を#3b82f6に変更する」
   - 変更箇所の行番号も記載すると良い

2. **影響範囲を明確にする**
   - どのファイルのどの部分が変わるか
   - それによって何が影響を受けるか

3. **実装順序を考える**
   - 依存関係を考慮した順序で記載

4. **リスクを洗い出す**
   - 既存機能への影響
   - セキュリティ上の懸念
   - パフォーマンスへの影響

## このskillを実行した後

plan.mdの内容を確認し、問題がなければ実装を開始してください。
実装中はplan.mdを参照しながら、計画通りに進めてください。
